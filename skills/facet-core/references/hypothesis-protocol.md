# Competing Hypothesis Protocol

Generate causal hypotheses only after the structural pattern and leak location are observed.

## Candidate generation

Create at least two plausible explanations that could produce the same pattern. Consider, where evidence makes them relevant:

- architecture or operating-model constraints
- market, legal, language, or distribution boundaries
- sequencing or maturity differences
- resource and cost trade-offs
- messaging compression
- measurement or disclosure gaps

Do not use stereotypes about leadership intent, culture, ethics, or competence as evidence.

## Attack each hypothesis

Run five tests:

1. **Support:** Which observations would be expected if this were true?
2. **Contradiction:** Which observed facts fit poorly?
3. **Alternative explanation:** Can another hypothesis explain the same pattern with fewer assumptions?
4. **Scope:** Does it explain only the observed product, market, and period, or does it overgeneralize?
5. **Falsifiability:** What obtainable evidence would weaken or reverse it?

## Selection rule

Select one likely cause only when it:

- explains more of the material pattern than competitors;
- conflicts with fewer observed facts;
- requires no unsupported intent attribution; and
- remains within the evidence scope.

If multiple explanations survive, do not force a winner. Write:

`X and Y both fit the observed pattern; Z would distinguish them.`

## Language rule

- Directly observed mechanism: `X constrains Y.`
- Indirect but best-supported explanation: `X may be constraining Y.`
- Several surviving explanations: `X and Y remain plausible.`
- No defensible explanation: `Unknown — the public evidence locates the leak but does not identify its cause.`
